数据中心利用率与资源优化 Streamlit Demo 项目 Summary for AI

一、项目定位

这个项目是 EOE（Energy Optimization Engine）中的“模块2：利用率与资源优化模块”。

用户正在开发一个面向数据中心和高能耗数字基础设施的作品集型 Streamlit demo，用于求职展示。这个 demo 的目标不是成为真实数据中心运维系统，而是作为个人作品集的一部分，展示用户具备“数据中心能耗分析、资源利用率优化、节能经济性评估、管理决策输出”的产品化能力。

核心展示逻辑是：

上传资产利用率数据 CSV
→ 识别低利用率资产和疑似僵尸资产
→ 估算这些资产造成的隐性能耗浪费和电费浪费
→ 估算资源整合、迁移、关停评估后的节能收益
→ 输出管理者和投资人能看懂的图表、KPI 和自动分析报告。

用户明确强调：
1. 不需要实时监控接口。
2. 不需要数据库。
3. 不需要真正服务真实数据中心。
4. 不需要复杂 SLA / 自动迁移 / 自动关停。
5. Demo 的目标是“能唬住企业管理者和投资人”，所以结果展示、逻辑自洽、页面专业感比真实运维复杂度更重要。
6. 用户不会 Python，只会复制粘贴、运行测试、反馈问题，所以后续回复要直接给可复制代码，不要讲太多专业实现细节。

3. core/metrics.py

负责计算资产级、分组级、类型级指标。

资产级指标包括：

平均利用率
最大利用率
最小利用率
P90 / P95 利用率
高负载时段占比
平均内存利用率
平均磁盘 IO
平均网络 IO
是否低利用率
是否基础疑似僵尸
是否有隐藏活动
是否业务保护资产
是否可迁移
最终是否疑似僵尸

判断逻辑：

is_low_util = avg_utilization < low_util_threshold

is_zombie_basic = avg_utilization < low_util_threshold
                  and high_load_duty < high_duty_threshold

is_zombie = is_zombie_basic
            and not has_hidden_activity
            and not is_business_protected

其中隐藏活动通过内存、磁盘 IO、网络 IO 辅助判断。

分组级和类型级会统计：

资产数量
平均利用率
低利用率资产数
疑似僵尸资产数
总耗电量
总电费
潜在浪费电量
潜在浪费电费
低利用率资产占比
疑似僵尸资产占比


4. core/power_model.py

负责功率、电量、电费估算。

核心逻辑：

estimated_power_w = power_idle + (power_peak - power_idle) * utilization_fraction

然后转换为 kW，再按时间步长计算 kWh。

注意：当前代码里转换方式是：

estimated_power_kw = estimated_power_w / 100
estimated_power_kw = estimated_power_kw / 10

这等价于除以 1000。写法有点奇怪但结果正确。后续可优化成 estimated_power_w / 1000，但目前功能不需要改。

还会计算：

平均功率
峰值功率
最小功率
资产周期耗电量
资产周期电费
疑似僵尸资产对应的浪费电量和浪费电费
按时间汇总的总功率曲线


5. core/consolidation.py

负责中级功能：资源整合测算。

核心功能：

筛选可整合候选资产：
is_zombie = True
is_migratable = True
is_business_protected = False

按整合率 consolidation_ratio 选出理论可下线 / 可迁移评估资产。

同时受 safe_util_limit 限制：整合后平均利用率不能超过安全上限。

输出：

也支持按 group 分组计算整合收益。
